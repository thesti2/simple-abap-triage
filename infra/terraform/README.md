# GCP infrastructure (Terraform)

Creates: APIs, Cloud Run runtime service account, Artifact Registry, Cloud SQL Postgres 16 (`db-f1-micro`),
Secret Manager secrets, Cloud Run service (FastAPI) with public endpoint.

The **SAP fix worker does not run in GCP**: it runs on the workstation that has the `sap-adt` MCP and connects to
Cloud SQL through the Cloud SQL Auth Proxy. So no VPC / VPN to SAP is needed here.

## Steps
0. Private inputs are git-ignored. Create them from the examples (values from `.env`: `GCP_PROJECT_ID`, `MODEL`, `TF_STATE_BUCKET`):
   ```
   cp terraform.tfvars.example terraform.tfvars   # set project_id, model
   cp backend.hcl.example backend.hcl             # set bucket
   ```
1. **Billing must be enabled** on project `<GCP_PROJECT_ID>` (Console → Billing → Link a billing account).
2. Create the state bucket once:
   ```
   gcloud storage buckets create gs://<TF_STATE_BUCKET> --project <GCP_PROJECT_ID> --location asia-southeast1 --uniform-bucket-level-access
   gcloud storage buckets update gs://<TF_STATE_BUCKET> --versioning
   ```
3. First apply (no Cloud Run yet):
   ```
   terraform init -backend-config=backend.hcl
   terraform plan
   terraform apply
   ```
4. Add secret values (kept out of Terraform state):
   ```
   gcloud secrets versions add abap-triage-openrouter-api-key --data-file=-   # paste key, Ctrl+Z, Enter
   gcloud secrets versions add abap-triage-langsmith-api-key  --data-file=-
   gcloud secrets versions add abap-triage-slack-bot-token      --data-file=-   # xoxb-...
   gcloud secrets versions add abap-triage-slack-signing-secret --data-file=-
   ```
   Set `slack_channel_id` in `terraform.tfvars` (channel ID `C...` from Slack).
5. Set `enable_cloud_run = true` in `terraform.tfvars`, then `terraform apply` again.
6. `terraform output cloud_run_url` → set Slack Request URLs `<url>/slack/events` + `<url>/slack/interactions`
   (see `docs/slack-setup.md`), and give `<url>/webhooks/xmatters` to xMatters together with
   `terraform output -raw xmatters_webhook_token` (header `X-Triage-Token`).

Note: the DB password and xMatters token are generated by Terraform, so they are in the (private, versioned) state bucket.

## Pause / resume (between work sessions)
Keeps database, Cloud Run URL and tokens; removes most of the running cost.
```
# terraform.tfvars: paused = true
terraform apply      # Cloud SQL stopped (only 10 GB storage billed), Cloud Run min instances 0
# terraform.tfvars: paused = false
terraform apply      # Cloud SQL starts (a few minutes), one always-on Cloud Run instance again
```
While paused, alerts from xMatters fail (database stopped) and the Slack bot does not answer.

## Destroy (done with the project)
Everything Terraform created is deleted, including **all alert data** (export first if needed).
```
# 1. main.tf: google_sql_database_instance.pg -> deletion_protection = false
terraform apply
# 2.
terraform destroy
```
Left over (not created by Terraform, negligible cost): the state bucket, the Cloud Build bucket
(`<GCP_PROJECT_ID>_cloudbuild`, created on the first image build), enabled APIs.

Recreating later: a deleted Cloud SQL instance name is blocked for up to a week, so bump
`sql_instance_suffix` (`v1` → `v2`) in `terraform.tfvars`. Terraform generates a **new xMatters token** →
update the xMatters flow header. The Cloud Run URL stays the same.
